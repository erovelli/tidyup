# tidyup-storage-sqlite

Default storage backend for [tidyup](https://github.com/erovelli/tidyup). Implements `FileIndex`, `ChangeLog`, `BackupStore`, and `RunLog` over bundled SQLite with WAL mode, BLAKE3 identities, write-ahead applied-state journaling, bundle-aware shelving, and retention-based pruning. Scan and migration identity indexing upsert every readable regular source/target file the walker can enumerate before semantic work; `file_processing` retains run-scoped roles, terminal states, stages, and failure reasons even when no `FileId` could be produced, with stage records committed in one transaction. `runs.capabilities_json` preserves versioned runtime provenance, maps future capability kinds to `Unknown`, and degrades an invalid diagnostic manifest to empty so status/rollback remain reachable. Versioned image/audio semantic artifacts are cached by content hash, model id, preprocessing version, and latent space as compact little-endian `f32` blobs; legacy JSON rows remain readable and `tidyup prune` deletes expired artifacts. Full text extraction/OCR/result fan-out across duplicate paths remains planned.
